# W5 标注界面原型验收

直接用浏览器打开 [`annotations/annotation_ui.html`](../annotations/annotation_ui.html)，无需服务、Python、安装依赖或网络。首次打开先显示当前版本的标注指南，关闭后进入 6 条演示记录；指令、指令解析结果与草稿用于交互验收，不是正式人工抽检数据。

## 建议验收顺序

1. 第 1 条沿用草稿，点击「确认并提交」，检查进度增加并进入第 2 条。
2. 第 2 条的草稿已按统一判据给出「部分覆盖／结构否」；展开字段判据，再把信心改为「低」，提交后应能在复看列表找到。
3. 第 3 条选择拒绝合理（「是」），显示最小缺失能力输入框；切到「否」后隐藏。切回「是」文字保留并可导出；选择「否」时可行表达依据写备注。
4. 跳到第 6 条，体验没有草稿时的逐项选择；返回已提交记录修改后，它会重新变为待提交，需要再次确认。
5. 刷新检查恢复，然后点击「导出结果」。只下载已提交记录，演示文件名为 `demo_annotations.json`；可从「加载任务」底部重新导入续标。

浏览器会按完整任务内容分别暂存，切换回相同任务可恢复进度。浏览器不允许存储时会显示提示，仍可操作和下载；下载文件只包含已提交判断，不包含尚未确认的修改。

旧版存档或导入结果没有当前口径版本时，会保留原选择并标为待复核，页面提供「下载旧版原始结果」。先下载备份，再按指南复核；不会自动翻转 Y/N，也不会自动把旧结果算作当前口径下的已提交记录。旧版草稿保留供比对，新打开的演示任务使用修正后的草稿。

## 标注指南与统一判据

界面把解析器产物称为「指令解析结果」，并在卡片及指南开头解释：它是一组描述对象、动作、时间关系和参数的检查条件，标注者核对其是否准确、完整地表达指令原意。符号展示区标为「形式化表达（AST）」。旧存档中的任务说明会在显示时沿用新称呼，不改写原始数据，也不因术语澄清要求已提交记录重新标注。

首次进入任务时阅读指南，后续点击「标注指南」随时查阅；字段旁「查看选项判据」与完整指南读取同一份 `fields[].help` / `options[].description`。概念解释来自可选的 `annotation_guide.introduction`，共同规则和边界示例来自 `principles` / `examples`，版本写在 `annotation_guide.version`；E7 当前为 `e7-2026-09-06`。关闭指南不会提交答案，同版本刷新不会反复弹出。

## 表示能力参考

「解析结果与上下文」下常驻当前能力摘要，点击「查看完整说明」或页头「表示能力」可查阅基础谓词、受限时序与逻辑、交互占位、角色与时间约束以及未支持项。未解析记录旁会直接显示「是 / 否 / 有歧义」的判断口径；这份参考对所有记录相同，不使用单条模型失败理由。

任务通过可选 `capabilities` 配置说明：`version` 为快照标识、`summary` 为常驻摘要、`scope` 为适用说明，`sections` 为 `{title, entries: [{name, description}]}` 分组。E7 未解析项旁的提示直接取自拒绝判断选项的判据；其他任务可用 `decision_guide` 文本数组。缺少能力说明的旧 W5 存档会显示有明确标记的内置参考，并提示核对本批次适用性；其他任务未配置时不显示 W5 参考。说明是只读任务材料，不写入标注结果。

验收可跳到第 3 条：先看能力摘要和拒绝判断提示，再打开完整说明核对 `until` 的限制与交互谓词的执行状态；关闭后应仍在同一条，保留已有选择。刷新后的旧存档同样可以看到能力入口。

## 加载外部任务

点击「加载任务」，在文件选择器中**同时选中**以下文件（按文件名识别，顺序不限）：

- `annotation_task.json`（也接受 `task.json`）：任务名称、说明、字段、选项、显示条件。
- `items.json`：记录数组，每条包含唯一 `item_id`、`context.instruction` 与可选 `fields` 初始值；E7 另需 `scene_id`、`instruction_id`、`status`。
- `drafts.json`（可不选）：草稿数组，每条包含 `item_id`、`fields`、简短 `reason`。

可直接加载 [`data/annotation_demo`](../data/annotation_demo/) 下的三份示例，它们与内置样例一致。正式任务不要设置 `demo: true`；正式 E7 导出文件名为 `parse_accuracy_annotations.json`，下载后由使用者放回对应数据目录。

`fields` 支持 `choice` 与 `text`；选项包含 `value` 和 `label`，`required` 控制必填。`when.status` 控制 parsed/failure 条件，`when.field` 配合 `when.equals` 引用前面已定义的判断字段。备注和缺失能力允许文字输入，其余判断为单击选项。

E7 的 `context.program` 可传入真实 `clauses` / `scope` / `body` 结构，或预先格式化的 AST 文本。格式化器保留角色、时间算子、参数单位和子句窗口；时间区间用秒，scope 用原始帧索引，不猜测二者转换。未知节点或不合法窗口阻止加载。

E7 只展示 instruction、AST 和独立草稿的简短理由，不展示原始记录中的 score、模型原因码、detail。`drafts.reason` 是专门给标注者的内容，生成方必须先提炼，不能把解析器 detail 原样放入该字段。

其他任务可以通过 `context_fields` 配置只读文本或指令解析结果，例如展示 A/B 两段候选描述，再用三选字段做偏好判断。原型尚未实现轨迹图片、视频或动画，不能据此视为 E1 完整标注工具。

## 导出约定与边界

- 结果是记录数组，含身份字段、当前适用的判断字段、`notes`、`draft_agreement`、`annotator`、ISO 格式 `date`，带版本指南的任务还含 `annotation_guide_version`；不含 AST、草稿理由或未提交记录。
- `draft_agreement` 比较当前适用的任务判断与草稿；备注不参与比较。没有草稿时为 `null`，不会伪造同意。
- 正式任务首次提交前填写一次标注者代号；演示任务预填「交互验收者」。同一结果重复导入不冲突；实际覆盖当前判断的导入会被拒绝。
- 本次仅交付交互原型与示例数据。正式 50 条抽样、LLM 草稿生成器、解析产物缓存和人工标注结果仍需单独完成，W5 D6–D7 整体未标记完成。

## 开发验证

零依赖格式化与导入边界测试：`node tests/annotation_ui.test.cjs`。

真实浏览器验收脚本为 [`tests/annotation_ui.browser.cjs`](../tests/annotation_ui.browser.cjs)，开发者需在外部测试环境安装 Playwright 与 Chromium，然后通过 `NODE_PATH` 和 `PLAYWRIGHT_BROWSERS_PATH` 指向该环境。脚本直接访问 `file://` 页面，验证点击、持久化、草稿隔离、下载、续标、通用任务切换、窄屏布局及无网络请求，并把截图与下载样本写到临时目录；这些依赖不进入原型分发包。
