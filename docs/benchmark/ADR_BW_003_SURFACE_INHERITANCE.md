# ADR BW-003：表述差异、安全继承与草稿撤销

状态：BW-06；有意收紧旧自动预填行为，不改变 metrics 或正式完成要求。

## 当前风险与决策

旧逻辑主要依赖共有 atom ID，并把 source 的新增要求直接复制给其他表述。ID 不包含全部表述语境，因此 precise 中独有的数字、否定、触发、因果或人工新增要求可能被带进 partial/vague。

现在完整保留两侧原文和逐 token 差异，分别提示数量、否定、对象/角色、关系、触发、顺序、修饰语、数值/单位及无法归类的文字；同时保留源/目标要求的增删与语义字段差异。分类只用于导航，不用于自动判定同义或计分。

任意非空白正文差异、不同 split/intent、源/目标要求集合或语义不同、未知字段和失效原文依据都回退完整审阅。只有空白归一后相同文字和相同源要求才允许复制未确认草稿；新增项逐条记录目标 query hash 与适用依据。CPD 源策略不同则保留未决定，不能因为 atom 相同就复制 CPD 判断。

这是保守边界，会减少旧数据上的自动预填；没有宣称继承覆盖率或标注效率改善。宁可显式完整重审，也不把未知差异当成已核对。已有目标草稿、例外及完成状态不清空、不覆盖。

## 独立提交与批审

每个 surface 保留自己的 task、表单、确认和最终提交，300 subjects 不缩减成 100 gold。离线队列按 split/intent 分组，但每题仍独立确认；对照视图及其源文字也进入浏览器收据摘要。

旧 notebook 的 atom/CPD 批审继续是可选工具；批次键纳入实际 dataset_split，不能跨 split。只填写空白、未确认的草稿。批审与适用的继承在 checkpoint 旁生成 `.batch-history` 审计目录，记录修改前后、绑定、目标 checkpoint、动作和目标适用依据；不写入包目录，不产生 gold。

撤销只恢复与动作后的内容仍相同、且未被确认的目标草稿。后续人工编辑或完成的记录保留并明确报告 skipped；继承源的确认不能被撤销目标草稿时回滚。准备记录先落盘，checkpoint 通过原 CAS 后才写 committed 收据；只有准备而没有 committed 的动作不能直接撤销，原件留待恢复检查。

## 兼容性与验证

旧 checkpoint schema 保持 0.2，不清空历史人工进度。BW-00 原始继承向量和旧 hash 保留作为历史证据；测试明确断言新协议对该不同表述输入返回未决定草稿，不偷偷改写旧期望值。原表单 compiler 的其他固定输出仍必须一致。

测试覆盖精确表述新增要求不泄漏、相同 ID 不足以继承、八类文字差异及未分类回退、相同文字的适用性记录、不同 CPD 保持未决定、跨 split 批审隔离、未变化草稿撤销、后续编辑/确认保护和 CAS 失败保留原件。

回滚需显式反向撤销本包逻辑并说明会恢复旧较宽松继承行为；不要删除 sidecar 审计记录，不把草稿标为人工完成。历史无 sidecar 的旧草稿迁移与疑问队列由 BW-07 处理。
