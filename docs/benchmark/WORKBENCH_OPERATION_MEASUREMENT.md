# Workbench 操作测量定义（BW-00）

状态：测量方案已登记，实测全部 unknown。对象为开发/合成试标题，不含正式 gold。BW-11 使用难度相当但内容不同的题交叉分配老/新流程，避免重复记忆。

## 三种成本分别记录

- 人的判断耗时：从开始阅读当前题到提交或暂存之间实际阅读、判断和编辑的秒数，排除明确离开任务的时间和界面等待。记录简单/复杂题的中位数与 p90；同样错误发现能力下越低越好。
- 界面延迟：打开、切题、保存、校验和恢复各自从动作到完成反馈的毫秒数；独立记录等待，不叠加为判断耗时。相同设备/浏览器/题包下越低越好。
- 材料不清成本：因源错误、缺证据、语义不清而暂停的次数与持续秒数，附结构化原因。不能把它自动算作界面问题或把疑问减少视为质量提升。

## 事件记录

每条观察至少记录匿名参与者、流程版本、题包版本、题目 ID、难度分组、时间、动作、等待时长、判断时长、原因与结果；不保存按键原文或个人身份资料。

计数包括页面切换、展开、重复确认、自由输入次数及字符数、失败校验、帮助使用和暂存原因。机械动作是实际观察到的动作，不能由 schema 字段数或 serialized slot 数反推。

另行记录植入的已知语义错误及是否被发现，确保提速没有依赖更快接受错误。试标输出只能标为试标，不能进入正式审阅定稿。

## 预先固定比较方式

沿用实施计划建议目标：同等难度机械动作减少约 50%，单题活动耗时中位数减少至少 30%。相对减少量为 `(旧值 - 新值) / 旧值`，旧值为零时不计算比率；这些是尚未测量的目标，不是收益。

同时报告简单/复杂题与 p90、源问题和已知错误发现情况。安全边界全部通过才可给出上线建议；真人试标缺失时结论必须为 unknown。
